## 三个表格的对比方法为什么这样选择

本节对应当前 [main.pdf](../paper/author-kit-main/main.pdf) 的三个 ACC 表。CCOE 的主要目标是保留已有的正确视图判断，并通过类别条件的表示交互改善联合预测。因此，对比方法需要同时覆盖整体分类能力、图与视图表示、可靠性与冲突处理、专家协作以及表示交互。每类方法承担不同的比较问题，不能只凭年份或方法数量评价基线是否充分。

**方法适合纳入比较，与原文结果可以直接移植，是两个判断。** 一个方法可以适用于当前分类任务，但原论文在其他数据集上验证；这种情况下应在当前数据和划分上复现，再填写结果。TUNED 就属于这一情况。

### 选型的主要考量

| 考量角度 | 选择原则 | 当前体现 |
|---|---|---|
| 任务与输入适用性 | 对齐多关系网络、图文特征或特征多视图的输入形式，核对视图数、维度和监督条件 | 图方法主要进入表 1；融合方法主要进入表 2、3；跨任务方法说明输入适配方式 |
| 与直接前作的关系 | 保留 CoE，检验进一步工作的实际增益 | 三个表均保留 CoE；本下载目录按要求不保存其论文和代码 |
| 对新增机制的针对性 | 每个关键机制都应有相应的已有方法或简单控制作为对照 | QMF/ECML 对应可靠性与冲突，TUNED 对应邻域证据，LMF 对应乘性交互，MvCGE/Mowst 对应专家组织 |
| 区分收益来源 | 考察图结构、表示学习、模态训练、融合规则等因素，避免把所有收益都归因于新协作模块 | NodeFormer/InfoMGF、MCR、Best-view/Mean/Concat + MLP 分别提供这些角度的对照 |
| 代表性与时间覆盖 | 同时包含经典参照和近期相关方法；机制相关性优先于单纯追求最新年份 | GCN/HAN/LMF 提供经典参照，2025–2026 年方法补充近期进展 |
| 公平性与复现可行性 | 使用共同的数据、标签预算和验证规则；保留合理的原方法结构，并披露必要适配 | 作者源码及提交记录见 registry/methods.json；文献结果与本地复现分开标注 |

这些角度用于解释基线集合的覆盖范围，不表示尚未运行的方法已经优于或弱于 CCOE。

### 表 1：多关系网络分类

**数据集：ACM、DBLP、Yelp、Amazon、MAG。** 这一组主要检验：CCOE 的收益相对于传统关系聚合、更强的图结构学习、多关系表示以及已有专家协作，是否仍然成立。

| 方法 | 比较角度 | 选用理由与需要回答的问题 |
|---|---|---|
| [GCN (2017)](table1/GCN_2017/paper.pdf) | 基础邻域传播 | 提供传统图分类参照，观察复杂协作相对于基本图编码的增益。用于多关系任务时应明确选择单关系图或采用何种统一输入转换。 |
| [HAN (2019)](table1/HAN_2019/paper.pdf) | 元路径与语义注意力 | 检验利用不同关系的重要性进行聚合，是否已经能够取得相近收益。 |
| [NodeFormer (2022)](table1/NodeFormer_2022/paper.pdf) | 潜在图结构学习与可扩展传播 | 提供结构学习对照，帮助判断收益是否主要来自更合适的连接结构和节点信息传播。 |
| [HDMI (2021)](table1/HDMI_2021/paper.pdf) | 多关系自监督表示 | 通过高阶互信息学习关系表示，检验多关系信息利用能力；其无监督表示与下游分类评估应分别说明。 |
| [DMG (2023)](table1/DMG_2023/paper.pdf) | 公共与私有表示解耦 | 提供保留共享信息和视图特有互补信息的对照，检验普通表示解耦能否解释分类改善。 |
| [InfoMGF (2024)](table1/InfoMGF_2024/paper.pdf) | 图结构优化与共享/特有信息利用 | 同时覆盖结构去噪、图融合和互补信息提取，是区分图学习与新协作机制作用的重要参照。 |
| [MvCGE (2025)](table1/MvCGE_2025/paper.pdf) | 图感知路由与逐层协作专家 | 与专家协作主题直接相关，检验已有的动态图专家组织是否足以取得相近效果。目前尚未获得可核实的公开代码，复现可行性需结合论文流程评估。 |
| [MRiemGNN (2026)](table1/MRiemGNN_2026/paper.pdf) | 关系感知传播与欧氏/黎曼空间协同 | 提供几何表示能力不同的近期多关系方法，考察更丰富的结构建模能否替代当前协作设计。关系编码应来自所有方法共有的数据输入。 |
| [Mowst (2024)](table1/Mowst_2024/paper.pdf) | 置信度驱动的专家混合 | 协调 MLP 与 GNN 专家，检验基于置信度选择或混合专家这一已有机制。它主要面向单图，不能将未经说明的多关系扩展视为原始官方设置。 |
| [CoE (2025)](https://proceedings.mlr.press/v267/wang25an.html) | 直接前作与两级专家协作 | 判断进一步工作相对于原有专家体系的收益。原文 reported 与本地 local 结果分列，以区分结果来源。 |

这一组同时保留经典方法和机制较接近的方法。GCN/HAN 的作用是提供基础参照；CoE、MvCGE、Mowst 的作用是检验专家协作设计；NodeFormer、InfoMGF 等则帮助区分图结构与表示能力带来的收益。

### 表 2：多模态分类

**数据集：ESP、Flickr、IAPR、NUS。** 当前输入是图像与文本的特征表示。这一组主要检验：可靠性重加权、冲突处理、模态训练平衡、一般表示交互以及面向协同信息的训练目标，分别能达到什么效果。

| 方法 | 比较角度 | 选用理由与需要回答的问题 |
|---|---|---|
| [InfoMGF (2024)](table1/InfoMGF_2024/paper.pdf) | 特征构图与图融合 | 提供将图文特征转为图结构后进行融合的对照，考察性能改善是否主要来自构图、去噪和共享/特有信息利用。 |
| [MMDynamics (2022)](table2/MMDynamics_2022/paper.pdf) | 特征级与模态级信息量 | 动态评估特征及模态的信息量，检验已有动态融合是否已经能有效利用不同质量的信息源。 |
| [QMF (2023)](table2/QMF_2023/paper.pdf) | 不确定性驱动的动态融合 | 提供根据模态质量和预测不确定性调节融合的对照，检验可靠性加权与本文更具体的协作条件之间的差别。 |
| [ECML (2024)](table2/ECML_2024/paper.pdf) | 类别证据与冲突意见聚合 | 直接处理存在分歧的视图意见，检验已有冲突感知决策机制与类别条件表示交互的效果差别。 |
| [MCR (2025)](table2/MCR_2025/paper.pdf) | 模态竞争与训练平衡 | 检验改善不同模态的训练和信息贡献，是否足以取得分类收益；其样本级误差分析也与判断保持的诊断相关。 |
| [SynIB (2026)](table2/SynIB_2026/paper.pdf) | 协同信息与联合预测 | 以训练目标促进跨模态协同，并分析单模态预测均失败的样本，是针对联合纠错问题较接近的比较方法。原文为 2026 年预印本。 |
| [LMF (2018)](table2/LMF_2018/paper.pdf) | 低秩乘性表示交互 | 检验一般乘性融合能否解释本文的收益。虽然年份较早，但与本文乘性交互的机制联系直接。 |
| [CoE (2025)](https://proceedings.mlr.press/v267/wang25an.html) | 直接前作的多模态专家协作 | 判断新设计对原有图文专家协作的改善，并与表 1 的比较保持衔接。 |

MCR 和 SynIB 主要提供训练目标，应明确它们所依附的编码器和融合结构，并设置对应的基础融合模型。模型比较应使用相同的图文特征，避免让某个方法额外使用更强的预训练特征而混淆协作机制的作用。

### 表 3：特征多视图分类

**数据集：MV-ACM、MV-Citeseer、MV-Prokaryotic、MV-Reuters、MV-Wikipedia。** 这一组检验方法能否用于多个特征视图，包括原始维度不同的视图，并区分可靠性融合、邻域证据和显式表示交互的效果。

| 方法 | 比较角度 | 选用理由与需要回答的问题 |
|---|---|---|
| [QMF (2023)](table2/QMF_2023/paper.pdf) | 不确定性驱动的视图融合 | 提供质量自适应融合对照。迁移到三视图、五视图任务时，应保留其基本融合原则并说明多视图扩展方式。 |
| [ECML (2024)](table2/ECML_2024/paper.pdf) | 多视图类别证据与意见冲突 | 检验证据级决策融合能否取得相近效果，并与表 2 的可靠性、冲突比较保持连续。 |
| [UVF (2026)](table3/UVF_2026/paper.pdf) | 视图强弱与差异化特征利用 | 根据不确定性区分视图强弱，再进行特征选择和动态融合；检验改善弱视图信息利用是否能够解释收益。 |
| [TUNED (2025)](table3/TUNED_2025/paper.pdf) | 邻域结构、跨视图依赖与冲突处理 | 与本文同时使用邻域证据和协作条件的设计较接近，用于检验已有邻域感知可信融合的效果。 |
| [AssoDMVC (2025)](table3/AssoDMVC_2025/paper.pdf) | 显式视图关联与动态融合 | 建模视图之间的依赖和交互，检验一般视图关联建模与本文类别条件交互的效果差别。 |
| [LMF (2018)](table2/LMF_2018/paper.pdf) | 一般乘性融合 | 提供跨任务的表示交互对照，帮助判断收益是否需要更具体的类别条件和残差协作设计。 |
| [CoE (2025)](https://proceedings.mlr.press/v267/wang25an.html) | 前作迁移到特征多视图任务 | 评价新框架相对于前作适配版本的增益。需要说明不同输入维度和视图数的适配方式。 |

TUNED 原文主实验使用 PIE、HandWritten、Scene15、Caltech101、Animal、ALOI、CUB、NUS-WIDE-OBJECT，**没有使用上述五个当前数据集**。它被选入表 3 的依据是机制相关性，其当前数据集的 ACC 需要复现。UVF、AssoDMVC 原文中的 Reuters/NUS 也与当前版本不同，不能按简称直接移植数值。各方法的具体结果适用性见 [论文侧 ACC 核查说明](../paper/author-kit-main/evidence/BASELINE_LOOKUP.md)。

### 三个表共同保留的简单控制

| 控制 | 设置 | 对应的比较问题 |
|---|---|---|
| Best-view | 用验证集选择表现最好的单视图，评估其测试预测 | 联合模型相对于单一信息源是否具有实际收益；帮助识别视图编码能力的影响。 |
| Mean | 对各视图预测概率取算术平均 | 一般的预测集成能达到什么程度，学习融合规则或表示交互是否带来额外收益。 |
| Concat + MLP | 拼接各视图表示，再使用 MLP 分类 | 普通联合分类器能否利用互补信息，是否需要本文更具体的协作结构。 |

这些控制应尽量使用相同的视图编码器、图输入和训练预算，并报告参数量；Best-view 的视图选择只使用验证集。它们是实验控制，不对应单独的论文下载文件夹。

### 结果来源与后续复现的判断规则

1. **文献参考与本地复现分别报告。** 当前新填入的 48 个带 dagger 标记的 ACC 全部来自 CoE 正式论文表 1/2，包括其对其他方法的评测值以及 CoE 自身 reported 结果；不是从各基线自身原论文移植，也不是当前工作区的新复现结果。原有 CoE local 与 CCOE 行使用已有本地实验结果。
2. **数据集名称相同不足以证明结果可比。** 核对样本、类别、视图数、特征提取和维度、图关系及划分。当前 Flickr 与 CoE 原文类别数不一致，文献值留空；表 3 的候选方法尚无匹配当前版本的分类 ACC。
3. **区分分类与聚类、指标与评估协议。** 明确记录原文指标，避免把聚类 ACC、不同任务的 F1 或不同监督预算下的结果当作当前分类 ACC。文献参考值不参与本地成对统计或当前的加粗排名。
4. **合理适配并披露信息范围。** 单图方法的关系输入、多模态方法的多视图扩展、无监督表示方法的下游分类头，都需要明确说明。固定数据与标签预算，使用验证集选择配置和检查点，并给予各方法合理的调参空间。
5. **同时考察整体分类与协作行为。** 对核心可运行基线，在相同参考分组下补充条件失配率 h0 和条件救援率 r0；与 ACC 一起判断已有可用判断的保留及参考盲区的改善。单视图 top-1 均失败并不自动证明概率平均无法纠错，因此 Mean 与表示交互对照都应保留。

来源可以通过每个方法的 paper.pdf、作者代码 README 和 sources.json 核对；数值来源及待复现原因也记录在 [论文侧核查说明](../paper/author-kit-main/evidence/BASELINE_LOOKUP.md) 中。


## 公平复现流程与可直接使用的 Prompt

以 conditional-joint-acm-tuning-1005 为参照的完整数据协议、环境规则、统一 log/exp 产物规范及 18 个方法的独立 Prompt 见 [REPRODUCTION_PROTOCOL_AND_PROMPTS.md](REPRODUCTION_PROTOCOL_AND_PROMPTS.md)。先执行 P00 公共模块，再逐方法复现；跨 Table 方法一次支持完整数据集范围。

- [数据身份与划分登记](registry/reference_datasets.json)：14 个数据集，固定训练种子 1024–1028，sample std 使用 ddof=1。
- [方法来源与运行范围](registry/methods.json)：18 个方法、103 个方法/数据集组合、515 个正式种子任务；尚未适配和运行。
- [环境只读探查](registry/environment_probe.json)：先测试 coe，有实际兼容性错误后才 clone；不改原 coe。

本目录现在是本地源码 Git 仓库。仅追踪核心代码、配置、许可证、必要说明及来源登记。PDF/数据/日志/权重留在磁盘但不追踪；各方法训练产物统一放其自己的 log/ 与 exp/。作者仓库原来的 17 份 Git 元数据保存在忽略目录 .upstream_git/，原提交也保留在 sources.json。初始提交由 Codex 生成；本轮没有启动基线训练、安装依赖或创建新 conda 环境。


## 公共基准 API（P00，协议 v1.1）

已实现 [shared.coe_benchmark 公共模块](shared/README.md)：支持全部 14 个数据集、冻结身份指纹、稀疏图输入适配、seed、验证 checkpoint、结果导出、重放对照和完整五种子汇总。数据身份规则未改变，方法训练器仍需逐一适配。检查产物保存在 shared/log、shared/exp，不纳入 Git。
